# 360° Product Spin — Capture & Publish Guide

> **⚖️ ملكية فكرية — اقرأ أولاً**
> الصور المُلتقطة هنا ملكية كايرو فولت الفكرية 100%. **ممنوع منعًا باتًا** نسخ أو تنزيل أي إطار 360° من مواقع الشركات المصنّعة (JBL, Anker, Joyroom, Harman) أو من أمازون أو نون. هذه انتهاك حقوق نشر مباشر + استهداف صريح لسياسة **Google Merchant Center** (Misrepresentation) وسنخسر الحساب. كل إطار لازم يكون تصويرك أنت، من مخزوننا الفعلي، على طاولة الدوران الخاصة بنا.

## Why 360° — لماذا نُصوِّر 360°؟

- **تحويل أعلى (Conversion):** المتاجر اللي بتعرض دوران 360° بيوصل معدل التحويل عندها لزيادة **13–47%** لأن العميل بيشوف المنتج من كل زاوية قبل ما يشتري (مصدر: Acquire Convert & Sirv retail studies 2024–2025).
- **ثقة أعلى + مرتجعات أقل:** العميل بيشوف الشكل الحقيقي، مفيش مفاجآت لما الكارتونة توصله.
- **SEO / Image Search:** كل إطار من الـ 36 بيدخل `image-sitemap.xml` تلقائيًا، فبنكسب 36 صورة قابلة للفهرسة لكل منتج بدل صورة واحدة.
- **AEO / GEO:** ChatGPT + Perplexity بيفضّلوا المنتجات اللي عندها تجربة بصرية غنية لما يوصّوا بمنتج.

**بديل رخيص لا نستخدمه:** فيديو 360° من موقع الشركة. أي مصدر خارجي = ممنوع (فوق).

## Camera settings — إعدادات التصوير (حرجة)

كل الإعدادات لازم تكون **يدوي (Manual)** ومقفولة عبر الـ 36 إطار. أي تغيير تلقائي بين الإطارات = المنتج هيرمش (flicker) في العارض.

- **Mode:** Manual (M) — مش Aperture Priority ولا Shutter Priority.
- **Aperture:** f/8 – f/11 (عمق ميدان يكفي الشكل من الأمام للخلف).
- **Shutter:** 1/60s أو أبطأ (الترايبود ثابت، مفيش داعي لسرعة عالية).
- **ISO:** 100–200 (أقل ضوضاء).
- **White Balance:** **Manual / Custom** — استخدم بطاقة رمادية أو حدد Kelvin يدويًا (5500K مع الـ softbox). **لا Auto WB.**
- **Focus:** Manual — ركّز على مركز المنتج مرة واحدة، اقفل العدسة، ومتلمسهاش تاني.
- **Exposure Compensation:** 0.
- **Image Stabilization / OIS:** **OFF** (على الترايبود بيسبب اهتزاز مصغّر).

**اختبار قبل البدء:** صوّر إطارين متتاليين بدون تحريك الطاولة، افتحهم في Preview جنب بعض — لازم يكونوا متطابقين 100% في السطوع واللون. لو مختلفين → في إعداد Auto لسه شغّال، ارجع وقفله.

## Turntable step — خطوة الدوران

- **الوضع القياسي (Recommended):** 36 إطار × 10° = دوران كامل 360°. سلاسة ممتازة، حجم كل frame ~30–60 KB بعد التحويل، إجمالي حزمة الـ 360 ~2 MB لكل منتج.
- **الوضع الخفيف (Optional):** 24 إطار × 15° = أخف بـ 33%، سلاسة أقل قليلًا. استخدمه فقط لو المنتج بسيط الشكل (مثلاً شاحن حائط صغير).

**علامات على الطاولة:** قبل ما تبدأ، حدد بلاصق ملوّن كل 10° (أو 15°) على حرف الطاولة عشان تعرف تدور بدقة. الطاولات الكهربائية الحديثة بتديك خيار "step per shot" مباشرة.

## File naming — تسمية الملفات (لازم دقيقة)

كل إطار Master يكون WebP مربّع (square) بحجم ≥ 1080×1080 بكسل. التسمية بالضبط كالتالي:

```
public/products/<brand-lowercase>/<slug>/spin/<slug>-spin-01.webp
public/products/<brand-lowercase>/<slug>/spin/<slug>-spin-02.webp
...
public/products/<brand-lowercase>/<slug>/spin/<slug>-spin-36.webp
```

- **Zero-padded دائمًا:** `-spin-01` مش `-spin-1`. المُولّد بيرفض غير كده.
- **الـ brand بحروف صغيرة:** `jbl` مش `JBL`، `anker` مش `Anker`.
- **الـ slug بالضبط زي المستخدم في الـ URL** (case-sensitive) — انسخه من `src/data/products/*.ts`.
- **صيغة WebP فقط** — مش PNG ولا JPG.
- **مربّع فعلًا** — نفس العرض × نفس الارتفاع. لو مش مربّع، المُولّد هيرفض الملف بدل ما يقطع أطرافه ويخلي المنتج يرمش.

مثال (JBL Charge 6):
```
public/products/jbl/jbl-charge-6/spin/jbl-charge-6-spin-01.webp
public/products/jbl/jbl-charge-6/spin/jbl-charge-6-spin-02.webp
...
```

## Post-processing — أمر واحد

بعد ما تنزّل الـ 36 ملف في المجلد الصح، شغّل:

```bash
node scripts/gen-product-spin-variants.js
```

اللي هيحصل:
1. المسكربت يلاقي كل الـ masters تحت `public/products/**/spin/`.
2. يتأكد إن كل واحد مربّع (يرفض غير كده برسالة واضحة).
3. يولّد جنب كل ماستر:
   - `<slug>-spin-NN-800.webp` (Desktop — quality 88)
   - `<slug>-spin-NN-480.webp` (Mobile — quality 85)
4. Idempotent — تشغيله تاني آمن، بيتجاهل اللي متولّد صح.

المسكربت بيمشي أيضًا تلقائيًا مع `prebuild` جنب scripts الـ hero والـ 480، فلو نسيت تشغّله يدوي، `npm run build` هيغطّيك.

## Publish — النشر (خطوة `git add` أساسية)

**العارض بيقرأ من manifest اسمه `public-image-paths.generated.ts`** اللي بيتولّد من `git ls-files`. الملفات اللي على القرص بس بدون `git add` **مش هتظهر** — تبويب 360° مش هيبان على صفحة المنتج.

الترتيب الصح:

```bash
# 1. تأكد إن الـ 36 master + الـ 72 variant (36×-800 + 36×-480) موجودين
ls public/products/jbl/jbl-charge-6/spin/ | wc -l   # لازم يطلع 108

# 2. git add
git add public/products/jbl/jbl-charge-6/spin/

# 3. تأكد إنهم اترصدوا
git status | head

# 4. Build عشان يتحدّث الـ manifest
npm run build

# 5. Commit + push
git commit -m "feat(spin): JBL Charge 6 360° spin capture (36 frames)"
```

## Verify — التأكد إن العارض شغّال

بعد ما الـ build يخلص:

1. **افتح الملف يدوي في المتصفح:**
   ```
   http://localhost:3000/products/jbl/jbl-charge-6/spin/jbl-charge-6-spin-01-800.webp
   ```
   لازم يرجّع 200 مع الصورة. لو 404 → مشكلة في التسمية أو مش `git add`.

2. **افتح صفحة المنتج:**
   ```
   http://localhost:3000/ar/jbl/portable-speakers/jbl-charge-6
   ```
   لازم تشوف تبويب جديد **"360°"** فوق الصورة الرئيسية جنب "الصور". اضغطه واسحب بالماوس أو بالإصبع — المنتج هيلف.

3. **تأكد من الـ image sitemap:**
   ```
   http://localhost:3000/image-sitemap.xml
   ```
   ابحث عن أي إطار من الـ 36، لازم تلاقيه مدرج.

4. **الوضع Dark:** لو الـ 360° tab مش ظاهر → معناها الـ manifest لسه مش شايف الملفات. ارجع للخطوة 3 في قسم "Publish".

## Common mistakes — أخطاء شائعة نتجنبها

- ❌ **Auto WB / Auto Exposure** → flicker بين الإطارات.
- ❌ **تصوير non-square** ثم "هصلحه في Photoshop" → المسكربت هيرفضه، صوّر مربّع من البداية.
- ❌ **PNG/JPG بدل WebP** → المسكربت هيتجاهله، لازم WebP.
- ❌ **`-spin-1.webp`** بدون padding → التسمية هتفشل.
- ❌ **نسيان `git add`** قبل الـ build → التبويب مش هيبان.
- ❌ **استخدام صور من jbl.com أو amazon.com** → مخالفة قانونية + خسارة Merchant.
